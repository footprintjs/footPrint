# Change impact — contributor reference

Read the relevant section before changing its owner. These constraints and qualifications were moved from the root work map; dated examples retain their original wording. Code and the current owner rulings remain authoritative.

<a id="cl-052"></a>

## Change-impact map

<a id="cl-053"></a>

- **Record sink** (10.1, P6) → foottrace's `RecordSink` port; the engine composes. `runner/recordSink.ts · RunRecord` (one per run; a same-executor resume keeps it) wraps the app's adapter: it SERVES before any byte leaves (the `opened` base through `RedactionRule · retainState`, `opened`/`closed` meta through `retainBoundary`; commits are the log's scrubbed bundles; attempt notes carry the served `AttemptRecord`), counts entries/losses (`getSnapshot().sink`), and under `onFailure: 'fail'` aborts the run's signal (`armRun`'s `stop`). `ExecutionRuntime`'s 6th ctor arg (`RuntimeRecord`) opens the root log at `{ logRunId: runId, drillPath: [] }`; `recordFor(mount)` hands a mount `[...parent drillPath, mountRuntimeStageId]` (`SubflowExecutor` closes it ok/failed/paused). `StageContext · noteAttempt` notes each kept attempt as it ENDS. `FlowChartExecutor · settleRecorded` closes the root log and flushes — a run WITHOUT a sink never enters it (no extra await, byte-identical). Same-executor resume continues the same root log (`resume` note, second `closed`; `RunRecord · beginLeg` resets the `'fail'` stop per leg); fresh-executor resume opens a new one (`resumedFrom`). KNOWN DIVERGENCE: with a sink a mount in a same-executor resumed leg is addressed under the ROOT log's `logRunId`; a plain log binds the current leg's runId (pinned in record-sink-mounts.test.ts; unify in a later packet). `fileSink` writes asynchronously (positional writes handed to the I/O pool at accept time, no O_APPEND; a NUL hole marks a torn write) with four bounds: maxEntryBytes, maxQueuedBytes (drop-and-count), maxBytes (then full), flushTimeoutMs; one sink per file per process.

<a id="cl-054"></a>

- **Nested diagnostic writes** → `DiagnosticCollector` uses the public `foottrace/paths` nested writers. They refuse denied selector segments, create own properties without inherited setters, and keep diagnostic concatenation/shallow-merge semantics separate from record union-merge semantics. Path rules have one implementation in foottrace; the engine does not copy them.

<a id="cl-055"></a>

- **Trace verbs** (`set|merge|append|delete`, `TraceEntry.verb`) → the record law lives only in foottrace. Its writer, replay, keyed fold, provenance and unknown-verb refusal share that implementation. Use the public record doors; do not add a verb switch to the engine. The canonical record contract and record-only differential controls moved with the package; FootPrint retains the engine byte-identity and admission witnesses.

<a id="cl-056"></a>

- **Write address** → ONE constant, `runAddress.ts · RUN_NAMESPACE` (an L4 leaf, C4), read by `runAddress` / `useAddressOf` and by `RedactionRule · verdictOfRead` / `retainState`; the frame's `RecordFrame` holds the address (C3). `SharedMemory` and the nested writers take the address as data and refuse a non-array; `TransactionBuffer` takes it too (C2, 9.45.0). `test/architecture/write-address.test.ts` refuses the namespace below L4, as a literal or a property — no exceptions since C4.

<a id="cl-057"></a>

- **StageContext.commit / dials** → ONE owner since 9.35.0 (F5): `memory/runPolicy.ts` — a frozen `RunPolicy` (the four dials + the `RedactionRule` + the mirror flag) built ONCE by `FlowChartExecutor · createTraverser` (run AND resume), handed to `ExecutionRuntime`, held BY REFERENCE by every `StageContext` (`inheritRun` in createNext/createChild) and by its `RecordFrame` as its encoding (`useEncoding`, through `StageContext · adoptPolicy`, the one place a frame's policy changes) and passed by `SubflowExecutor · executeSubflow` to the nested runtime BEFORE the seed. A fifth dial = the policy type + its consumer. The old per-dial `use*`/`get*` and `enableRedactedMirror` were removed in 9.36.0 (no compat shims — owner ruling). `commit()`'s FIRST act (9.23.0) is `materialiseWrites` — the `writeTracking` retained form is taken there, once per key, from `_pendingWrites` (bare references + the write-time verdict); anything that reads `_stageWrites` goes through `retainedWrites()` (a non-consuming fold, so a mid-run snapshot is honest), and `discardStaged` drops the pending map with the rest.

<a id="cl-058"></a>

- **runtimeStageId format** (`#`/`/` delimiters) → foottrace owns build/parse/read and the brands `RuntimeStageId`/`ExecutionIndex`/`CommitIdx`, all on its root door. The engine's `ids/reservedIds.ts` owns `refuseReservedId`, and `ids/branchSegment.ts` owns the generated `~` grammar. Every engine reader uses the public codec; no local parsing copy. R5: every ID door (22 at build, plus the run-time dynamic-StageNode door) refuses `#` and `/`; stage IDs may contain `~`. `TraversalContext` has one constructor (`engine/traversalContext.ts`), with depth read from the runtime ID on every stamp.

<a id="cl-059"></a>

- **Subflow id prefixing** → ONE prefixer since 9.37.0: `engine/graph/prefixNodeTree.ts`, used by the builder AND the traverser (eager, lazy and `parallelForEach` mounts — lazy/branch roots were unprefixed before 9.37.0, so branch ids collided); change it + stageMap key composition + resume drilling; the builder's eager mounts all go through `FlowChartBuilder · _mountSubflow` (F10). test/lib/engine/branch-segment-prefixer-equivalence.test.ts stays as a guard.

<a id="cl-060"></a>

- **Checkpoint shape** (format 2 since 9.44.0, LEAN: only what resume reads + the pause's record — no `executionTree`/`subflowResults`; size independent of run length, pinned by test/lib/pause/checkpoint-size.test.ts; 9.39–9.43 refuse format 2, so upgrade readers before writers) → `runner/checkpoint.ts · buildPauseCheckpoint` ↔ `pause/record.ts · decodeCheckpoint` (one upcaster drops v0/v1 fields) ↔ `runner/resume.ts · planResume` (validation via `pause/record.ts · decodeCheckpoint`) ↔ `ResumeEntry.plan` (the path's mounts + captures + dispatcher continuations, the `pendingPauses` queue; refused up front when unwalkable, ambiguous, or a pending record is not a sibling) ↔ `SubflowExecutor · executeSubflow` resume hop (seed from the capture in place of the mapper's values — the mapper still runs, for the args — FIRST entry only) ↔ `ChildrenExecutor · raisePauses` (fills `pendingPauses`). 9.28.0 adds ONE optional field, `pendingPauses` (present only when parallel siblings wait); the redaction law adds `redactionMarks` (names only, present only when the run marked something); every stored checkpoint enters through `pause/record.ts · decodeCheckpoint` (`checkpointVersion: 2`, one upcaster from unversioned v0 which drops the legacy `continuationStageId`, one validator, one message set; 9.39.0). Pinned: a 9.27.0 checkpoint resumes, test/lib/pause/resume-real-chart-9.27.0-checkpoints.test.ts.

<a id="cl-061"></a>

- **Committed-state writers** → copy-on-write staging and commit belong to foottrace. The engine composes `RecordFrame` rather than editing its internals or the shared heap. Engine tests retain the committed-generation, borrowed-reference and counted-cost witnesses; record-only mutation controls live with the record implementation.

<a id="cl-062"></a>

- **Redaction** (9.19.0; the law restored to owner ruling (a)) has ONE owner of the DECISION, `memory/redaction.ts` (L4 since C4): `RedactionRule` (verdict per user-level path: `clear | whole | fields`) and, per staged write, `decideWrite` → `inheritByIdentity` → (the record writes) → `markStagedWrite` (the marks, only once the write staged — a failed `$update` leaves no mark in `redactionMarks` or the report); the BYTES are the record's (`RecordFrame · write` registers `scrubOf(verdict)`, foottrace's `memory/scrub.ts · scrubPatch` writes the log's placeholder at commit; no record file imports `redaction.ts`), carried on the run's `RunPolicy` with the four dials (F5). THE LAW: a policy covers EVERYTHING the library retains or serves — log (both encodings), mirror, stageReads/stageWrites, every recorder event inline and deferred (and the rows built from them), narrative, snapshots, diagnostics, pause payloads, boundary records, logger lines — and NEVER the live heap or the resume checkpoint. The two true exceptions are the caller's own values: the `run()` rejection and the live fork result. It selects by NAME, never by content: state by path (`verdict`); a record handed out whole (root input/output — `FlowchartTraverser.execute`; subflow seed/exit — `SubflowExecutor`; pause payload — `engine/handlers/servedPause.ts`; thrown value — `retainStageError`) by its keys at every depth plus declared `fields` under a key of that name (`retainBoundary` — one decision per PATH via `servedByPath`: copy-on-write per path, the visited set only the current path's ancestor stack, a cycle edge landing on the served copy; a path rule is exact under shared references, a key-NAME rule masks a shared node everywhere); a diagnostic entry as the record `{ [name]: value }` (`retainDiagnostic`; `policy.diagnostics` ADDS diagnostic-only selectors, the only ones that reach flow-message text); a subflow mapper's copy by TAINT (`MapperTaint`, asked by `SubflowInputMapper` for both mappers; the `parallelForEach` items selector counts selected reads via `StageContext · selectedReads` and marks `item`/`into`): a value passed under its own name keeps that name's verdict, an object by reference (or the whole handed record, as fields) keeps its source's, anything computed after a selected read is marked whole (conservative); never value equality across names. A mark is a NAME, run-wide, until the key is deleted where its value lives: a mark remembers every PLACE a hidden value under its name landed (`memory/markPlaces.ts · placeOf`: the heap and the address the write LANDS at, read from the absolute path, so a `setGlobal` of a namespaced frame is the root). THE LAW of how a mark ends: a delete ends it only by taking away its LAST place; a delete at a place where no value of that name landed changes nothing; a value still on its way (the fan-out's `item` / `into`, decided before any branch runs) holds a place of its own until it has landed (`pendingPlace`, let go by `ParallelForEachHandler` after its results write); and a delete ends nothing while it is only STAGED (`markStagedWrite` returns its claim): the frame ends the mark once its commit has landed and the key is really gone from the state (`StageContext · endMarksOfLandedDeletes`), so a try a retry throws away, a failed commit, and a stage that deletes a key and writes it again all end nothing. A new "decide now, write later" site must hold a pending place the same way. A pause carries the marks (names only) to the resumed run, where they stay (`FlowchartCheckpoint.redactionMarks`, checked by `pause/record.ts`). A thrown value is walked with its `cause`/`errors`; an object a mapper passes on by reference is scanned for the selected values it read (planted → fields). Name-only patterns (`needsPath` false — no `.`, lookaround, or escape/class that can match `.`) are decided per object, so the walk shares decisions per (object, targets) — linear on a DAG or a linked history; only a path-dependent pattern walks paths, and past 1,000,000 visits it serves the unvisited remainder as the placeholder (one dev-mode warning), never fails the run. Inside a stage, an OBJECT read under a selected name keeps its rule WHEREVER the stage writes it, and so does every object inside it (`memory/selectedObjects.ts`: the frame REMEMBERS a selected read with its members, each with the rule its place gives it; `redaction.ts · inheritByIdentity` FINDS them in a value about to be written, decided before the write). A place below a top key is handed to the TOP key as a FIELD (`a` hides `b`), never as a mark of the dotted name: the typed scope writes a nested change as a write of the top key, and only a field of the top key covers that. A list (a `Map`, a `Set`, an `Error`) that holds one is hidden whole; a key the record's scrub cannot reach (`__proto__`, `constructor`, `prototype`, a dotted key below another) cuts the place back to the keys above it (`redaction.ts · fieldsHiddenBy`; `scrubOf` hides a value whole when a policy field names such a key). A read with NO key remembers every selected value it hands out (`StageContext · noteKeylessRead`). Only what is NEW against the key's current value is searched (same object as before = skipped; the SAME object written back and a container met at a second place are searched whole), so a list write costs one comparison an item, not a deep walk (`bench/hidden-object-writes.ts`). COST LAW: a key takes one hidden field for each hidden object put below it, so the number of hidden places comes from DATA, and every step asks a list ONCE, never once for each member: what a list of paths says is read once and kept for the list when the list is FROZEN (`selectedObjects.ts · read`; the library freezes the lists it makes, `RedactionRule · inheritFields` and `servedPlaces.ts`; a policy's own `fields` list is the caller's, who may push onto it between two runs, so its reading stays with the rule object), all the places one search found are handed to the key together (`inheritByIdentity`), and the serving walk asks a node's targets once for the node (`memory/pathTargets.ts · stepsOf`, grouped by first key from 16 targets on; no data-sized list is ever spread into a call). `bench/hidden-object-scaling.ts` runs twenty shapes at N and 4N and marks a square; a new step that handles hidden places gets a shape there. The key's own old value moved below its new one (`a = { prev: a }`) is not walked: when it holds something the key's name hides, the place it moved to is hidden whole (a field path would grow with every move). A value that holds itself and a hidden object is hidden whole at its place (a field cannot be hidden through the edge back; a field the POLICY names inside such a value still shows through it, that scrub is foottrace's). The record takes a value as it stands at COMMIT, so every key the frame wrote is searched once more then, against the committed base. The frame's side is ONE helper, `memory/hiddenObjectTrail.ts` (held by `StageContext`, asked at a hidden read, at a write — `stage` is steps 2 and 3 of `stageWrite` — at commit and at a discarded try): it owns the remembered objects and the written keys. The search at commit finds ONLY what was put in after the write, so that no record changes because a stage read a key: it passes over a place the key's NAME hides already (`Search.named`, carried down the walk), an object the key SHOWED when it was written and that was not hidden then (`ShownObjects`, per written key: `s.public = h; s.hidden = h` stays shown under `public`; filled by the search at the write, by a note of the containers a merge makes, and once at the stage's first hidden read for the keys written before it), and a place that holds what the committed state held there (a read after the first write is a private copy). A key that gains a hidden place there is staged again as a `set`. What the frame KEEPS of each write (`_pendingWrites` → the execution tree's `stageWrites`, the commit event) is given its verdict in the same pass (`HiddenObjectTrail · keep`): a kept value the record holds takes its key's rule as the search left it; the kept value of a MERGE is the caller's patch, which the record copied at the merge, so it is searched itself and what is found is hidden in the kept form only (`redaction.ts · keptUnder`; no rule changes). The stage's INPUT is a read door too: `ScopeFacade · getArgs` → `StageContext · noteInputRead` → `HiddenObjectTrail · rememberInput` asks the ONE rule that serves the input (`memory/servedPlaces.ts · placesHiddenIn`: `RedactionRule · retainBoundary` with a marker for the placeholder, the served copy walked beside the original and read back as paths; kept for a record that cannot change — every container frozen and plain — while the rule's policy and marks are the same, because every stage of a run is handed the same input) and remembers every place it hides, as fields of the input (so `scope.copy = scope.$getArgs()` keeps them, texts too); an input the rule cannot serve is remembered whole; never counted as a selected read. One limit on EVENTS: a write is searched for what is new in it, so an object changed in place and then written again under the same key, still at its place, shows in that write's event (the record does not show it). A primitive (also by a spread) is selected by its own name only. `StageContext.stageWrite` is the ONE write funnel (facade writes, subflow seed, outputMapper merge-back, resume re-seed) and `getValue` retention asks the same rule; the facade asks it for read/write recorder payloads. An inert rule never enumerates a payload. What a stage's own code puts in a record is served where it is made, one form everywhere, no second scrub: a threshold by `RedactionRule · serveThreshold` (the one law, whose answer is what the row keeps: key verdict through `verdictAt`, not the marked set; the frame's `taintedReads`, asked after the filter's own read, where a key listing is no read (`StageContext · inspectValue`) and a keyless read counts by `holdsSelected`; `carriesSelectedKey(args)`; one read, `readThreshold`, a detached frozen copy made with no author code, which is what the shape check sees and what the row stores, so nothing can change it afterwards; what the copy cannot hold faithfully (a `Map`, an accessor, a hidden key, a Proxy) is a hole under any active rule, a `Date` is served, and an inert rule keeps the reference; a hole is the placeholder plus `thresholdRedacted`, because `redacted` speaks only for the actual value), and a rule's thrown text, a break reason and an idempotency key by `retainStageText` (`errors.matchError`, `logs.breakReason`, `logs.idempotencyKey`). `decide/` and `filter/` hold no rule: they get `RedactionRule · evidenceRule`'s answers through `ScopeRuntimeTarget · decisionEvidenceRule`; `handlers/breakFlag.ts · createBreakHandler` serves the reason, so the flag only ever holds the served form. A rule's `label` is author text and stays as written; see the scope guide. `emitPatterns` is the one separate scrub (`$emit` payloads, by event name). Two placeholders, historical, one per owner: log/mirror `'REDACTED'` (`foottrace/write · LOG_PLACEHOLDER`, a record byte), scope-tier `'[REDACTED]'` (`redaction.ts · SCOPE_PLACEHOLDER`). See `docs/guides/scope.md` → "The one law". Capture the retained form at runtime; no second tree walk or recorder-local policy.

<a id="cl-063"></a>

- **Diagnostic retention** → `DiagnosticCollector` asks the current run rule before merging/storing: a named entry maps to the state key of its name (the run's keys/patterns/marks/fields, at every depth of the value), then the opt-in `RedactionPolicy.diagnostics` selectors (same path algorithm, rooted at the channel). Its internal retained-write bridge supplies legacy facade emits. Existing writers stay void. Only flow-message description/rationale are payloads (no name — diagnostic selectors only); keys/topology/timing stay present. Dynamic capture uses a per-visit engine flag, not a diagnostic bag. A redacted `logs.deciderRationale` also reaches decision explanations. Checkpoints keep retained diagnostic bags but preserve operational state; no retroactive scrub. See the scope guide's diagnostic contract.

<a id="cl-064"></a>

- **Traverser phases** → node-shape reads must use eff* overlay accessors or dynamic StageNode returns break; tail continuations must return ContinuationHops or stacks regrow; decider flat-dispatch must keep InvokerStamp or pause loses its invoker. A stage that RETURNS a sub-flowchart is mounted once per return, and its definition is SELF-CONTAINED: Phase 4 puts the returned `subflowDef` on the overlay (`subflowMeta.definition`), Phase 0 takes it off (`takeReturnedMount`), mounts its root through `NodeResolver · mountOf` and hands the definition to `SubflowExecutor · executeSubflow`, which records its structure and layers its own `stageMap` / `subflows` over the run's for the nested traverser. Nothing about it is read from the id registry, which keeps the FIRST definition under an id (`autoRegisterSubflowDef`). Returned CHILDREN still carry over for the run (pinned; per-visit is held for the next major).
