# Typed first-boundary decision

One job: expose the existing witness's decision as data without parsing or changing its diagnostic strings. Existing `witnessClause` becomes the exact formatter over this decision, with no optional #124 ports in its legacy call. All existing hand-made branch tests keep their exact expectations.

Every BUILD fold-back check happens before any optional proof. The old baseline non-fold-back cause is `admitted-record-9.30`; its coordinate comes from the actual native commit when observed, or is explicitly `not-collected` on legacy hand-made rows. It never invents an operation. A coherent first changed commit may use only an actual closed #124 cause for THAT index; a later cause cannot clear an earlier corruption. Identical commits may use only the strict exact retained-slot relation. Named causes/coordinates stay in the returned data; the formatter alone remains the old string interface.

After a proved first boundary the established downstream rule remains. Generation, no-alias, real checkpoint-start rejudgment and same-build paused/direct laws are not moved into this unit and stay unconditional at existing owners. Root binds the optional ports to real receipt constructors and the closed branch strategies, never a generic true/false callback.

A historical ADMITTED program can also have an earlier #124 FIRST. Its FIRST keeps the actual #124 name and coordinates; `also: {cause:'admitted-record-9.30',commit}` separately records the first later baseline nonfolding commit, with every BUILD commit folding. `hasAdmittedRecordEvidence` requires that old evidence at its own actual index. The old literal list is unchanged; neither evidence waives the other, and later evidence never clears an unproved earlier boundary.
