## One guard, closed strategies

* `program.ts` reads the actual immutable program pointer and encoding.
* `common.ts` requires exact program/leg, every BUILD fold-back, the FIRST raw differing commit, coherent baseline there, checked tombstone/native read pair, real operation/call membership and order, and actual inner encoder/receiver/frame/buffer/epoch joins. These checks execute before strategy dispatch.
* The closed WRITEBACK or CHART strategy returns only actual declared StageContext write rows. It never returns a cause.
* `nativeWrites.ts` independently accounts for EVERY actual write call and every stage-origin native buffer write inside the operation. Direct calls must have exactly one corresponding physical producer, the exact argument value/object ID, frame, buffer and epoch. An extra write cannot hitchhike beside a valid read.
* The unchanged outside-operation native prefix must match before the first commit. Only after all common and strategy checks succeed does the facade return the named cause/coordinate. The established downstream clause remains the existing owner's responsibility; generation, no-alias and actual checkpoint-start controls remain unconditional.

For `copy`, the destination differs from the read key. The common guard verifies the actual canonical read ends with its actual user path/key operand, takes the remaining OBSERVED prefix, then requires the actual write producer address to equal that prefix plus the actual write operands. It never recognises a `runs` spelling or guesses a namespace/global fallback. `checkedPair` still requires the positive base provenance; missing-base/global-root fallback remains denied.

## Supported data and limits

Existing delReadBack covers exact delete/read, original edit helper invocation and SAME-object set/merge, including the new undefined no-op branch. Its semantics and old tests stay intact.

The frozen host helper covers same/copy (including exact whole-object identity), primitive spread, selected primitive mergeFirst, dense primitive batch, and literal/revert forms under its exact call profiles. CHART same/copy after deletion and different copy destinations now receive the SAME common guard as writeback. Literal append/restoring forms can prove a first changed commit only when their actual declared write plans differ. A literal-only missing-key fallback with identical old/new writes is explicitly refused as a first-commit cause.

Nested materialised embeddings, proxy-heavy selected branches, unsupported call tails/counts and missing IdentityGraph facts remain unproven. The helper's top-level `fresh` means different-from-that-read ID, not global allocation provenance. No equal-content alias inference is introduced. Multiple changed operations before the first commit may fail the strict outside-operation prefix; this draft does not invent a causal suffix or overlay to admit them. Root diagnoses actual reached cases from real receipts.
