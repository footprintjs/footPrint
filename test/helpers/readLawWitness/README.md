# #124 read-retention relation

One job: admit only joined, changed read-delivery slots when commits are byte-identical. `checkedPair` requires the real successful tombstone, same local frame/buffer/epoch/leg, canonical address, no intervening re-establishment, old return equal to canonical own-base provenance (or the strictly observed original heap fallback described below) and new native undefined. `equalNativeTrace` is the ONE comparator: within proved operation windows it compares native semantics and owner/frame/buffer/epoch joins exactly; outside them it compares semantic methods, arguments, results, outcomes, ordering, canonical addresses, values and encoder bytes. Actor placement outside those windows is judged by the existing record-level R13 view. Only proved selected return facts and same-object auxiliary operands differ in its PRIVATE comparison representation; native values and kept outputs never change.

Every kept string outside the exact observed leaf stays exact. Re-serialization is allowed only for the closed JSON leaf form and only when parse/stringify reproduces the input line exactly; arbitrary JSON is never normalized. Live state, fold, checkpoints, errors and commit fields have no admission path. Execution-tree locations accept only actual next/children edges and validate the native stage/execution owner. An extra difference fails closed. Duplicate slot/native/operation claims fail. A named entry that stops differing fails and must be removed.

`read-line` is the fixture's existing `bytes(native ?? null)` delivery. Stage-read sites additionally require the SAME retention capture object attached to the actual native read fact; a placeholder string or a guessed stage/key cannot supply that port. Operation bounds and retention facts must come from the same actual observer, joined by the existing binding ports; no missing operation, frame, retained slot or identity is synthesized. Missing evidence returns unproven. Subflow-history read paths are deliberately unsupported rather than granted a free path.

Adjacent tests are inert rule controls, not execution of either engine. They are unrun by this author. Root retains original old-admission, redaction, generation/no-alias, lying-build and checkpoint-start controls. There is no generator, seed, shrinker, corpus, golden or `src/` change here.

For an absent/undefined canonical base, heapFallback requires an actual original baseline SharedMemory.getValue call with exact run/path/key and returned identity, explicit candidate no-call plus native undefined, and unchanged own heap generation/facts from tombstone through read. Pre-delete facts must agree across engines; local object IDs never cross engines. The original canonical-own-base proof stays separate and unchanged. Unknown or unbound memory tiers refuse, and this alternative grants no auxiliary-read or downstream-write exception.

The root-array JSON operand profile joins actual primary/auxiliary raw object identities within one original member operation span. Its count and operand facts travel as auxiliary evidence on the existing read-after-delete cause. The comparator validates complete original heap origin receipts before omitting only the proven auxiliary stage rows from its private semantic view. Every other native semantic field and every residual kept byte stays exact; actor placement outside the windows remains record-owned. Exact native commit count and order must match all outer witnesses.

`nativeTraceComparison` records the exact per-engine operation bounds, semantic cross-engine field class and record-level R13 actor ownership. The neutral import-free `nativeTraceFacts.ts` type is shared with Decision; metadata is emitted only after an actual named cause passes its existing proof. It is never a new admission input.
