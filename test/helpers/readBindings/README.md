# Actual read bindings

Intended destination: `test/helpers/readBindings.ts` + folder. This unit does metadata pairing, not engine execution or branch admission. The basic driver supplies one actual leg, exact unchanged program JSON, native receipt, operation spans, commits and kept strings. No frame/read/epoch IDs are synthesized.

`pairObservedReads` pairs exact operation coordinate + actual returned read occurrence + method/argument facts. Span pointers must name the actual applied program operation; spans are unique. One operation must have one actual native frame. A direct pair requires eligible tombstone/read evidence on BOTH engines; one-sided rows remain in the exact raw trace, without poisoning an earlier FIRST candidate. Local tombstone/native/base checks remain in checkedPair. A missing canonical own base needs the strictly observed original heap-fallback proof; equal contents at a global key never become provenance. Extra/missing calls are not aligned by searching a matching key/value. The within-op occurrence is recorded as an extra OperationRead field and independently checked against actual native call order.

`bindRetainedPairs` is separate and used ONLY for identical-commit shape1. NESTED/WRITEBACK explicit returned getValue count must equal the exact retained read-line count, every read must be operation-bound, each selected read must have the same line ordinal, and the existing closed delivery checker validates both actual native returns through the existing `?? null` delivery. CHART has no invented reads-list field.

Stage slots require the SAME actual native retention object and the last actual retaining owner in its frame. An earlier valid read remains paired for native and explicit delivery proof, but claims no final stage slot when a later actual same-run/frame/key owner has its own retention nativeId. All later provenance on BOTH sides is still validated; missing, unknown, overlapping or ambiguous owners refuse, even after a valid later shadow. Selection never searches by value. Native branch pairing stays separate because a primary branch read need not remain the final retained slot. Only actual next/children stage trees and the observed `treeContext.stageContexts` roots in the two declared subflow-result fields are traversed. Stage/runtime-stage identity must map to exactly one native frame. No live heap, history, fold or checkpoint data is searched for a replacement. The exact residual-string relation still protects every other byte.

`causeAtFirstCommit` assembles actual rows/spans by nativeId and checks it is the first raw differing commit. It RETURNS A CANDIDATE, never an admission. Root runs the closed WRITEBACK/CHART branch strategy and the common first/inner-producer/prefix guard before a typed named decision. `commitCoordinate` reports the actual native commit for old9.30 causes; missing legacy metadata is explicitly not-collected, never a default stage.

Pause remains separate per actual leg until basic-family proof. Do not merge native receipts or project checkpoints to create togetherness. Generators, source operations/order, corpus and old exclusions stay unchanged. Private input/source layout ambiguity is a harness proof failure, not a product red.
