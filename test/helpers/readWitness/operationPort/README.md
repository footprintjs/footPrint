# Fixture operation metadata — static author draft

One job: label the existing synchronous fixture operation and snapshot the existing edit helper's input/output, with the native observer's clock and WeakMap. It does not execute a replacement interpreter or edit algorithm. Native wrappers must attach the active immutable coordinate to their own actual call facts. Capture failure makes proof unusable while the fixture still returns/throws its original value.

Use `within` around the unchanged operation body, and `edit(got, o.n, editForWriteBack)` in place of the one existing `editForWriteBack(got, o.n)` call. There is still exactly one original edit invocation. The operation pointer references the same applied program, not an independently regenerated sample. Nested/parallel labels are unsupported until actual per-invocation ownership is added; never share a mutable global operation across concurrent branches. Root must prove unchanged instrumented/uninstrumented bytes on each actual engine and fixture family before any named admission.

The native port is not yet supplied by the integrated observer. It must use that observer's clock/object map/value snapshotter; a second identity map cannot prove the SAME object. No tests here have been executed by this author.
