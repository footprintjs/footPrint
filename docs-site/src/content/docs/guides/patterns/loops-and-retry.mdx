`.loopTo(targetStageId)` creates a back-edge to any earlier stage. Pass the stage **id** (the third argument to `flowChart`/`addFunction`), not the display name — `loopTo` validates against known ids and throws if you pass a name. The loop continues until a stage calls `scope.$break()`. This enables polling, pagination, retry, and iterative refinement patterns.

## Basic loop

```ts
import { flowChart, FlowChartExecutor } from 'footprintjs';

const chart = flowChart<{ counter: number; target: number }>('Init', async (scope) => {
  scope.counter = 0;
  scope.target = 5;
}, 'init')
  .addFunction('Increment', async (scope) => {
    scope.counter += 1;
    if (scope.counter >= scope.target) scope.$break();
  }, 'increment')
  .loopTo('increment')
  .build();

const executor = new FlowChartExecutor(chart);
executor.enableNarrative();
await executor.run();
// Narrative: "On pass 1 through Increment." ... "On pass 4 through Increment."
```

## Retry with backoff

For a stage that fails and should run again, prefer the built-in policy: give the stage a `retry` option (`RetryPolicy`, with `exponentialBackoff` building its `backoffMs`), or compose a retry loop with `.addRetryLoop()`. Every attempt is then part of the record. See [Declarative Retry](https://github.com/footprintjs/footPrint/blob/main/docs/guides/error-handling.md#declarative-retry). The hand-built loop below shows `loopTo` and `$break()` only.

```ts
interface RetryState {
  attempt: number;
  maxAttempts: number;
  result?: string;
}

const chart = flowChart<RetryState>('Init', async (scope) => {
  scope.attempt = 0;
  scope.maxAttempts = 3;
}, 'init')
  .addFunction('CallAPI', async (scope) => {
    scope.attempt += 1;
    try {
      // Simulate flaky API
      if (Math.random() < 0.5) throw new Error('timeout');
      scope.result = 'success';
      scope.$break();
    } catch {
      if (scope.attempt >= scope.maxAttempts) {
        scope.result = 'failed after retries';
        scope.$break();
      }
      // Wait before retry
      await new Promise((r) => setTimeout(r, scope.attempt * 100));
    }
  }, 'call-api')
  .loopTo('call-api')
  .build();
```

## Pagination

```ts
interface PaginationState {
  page: number;
  allItems: string[];
  hasMore: boolean;
}

const chart = flowChart<PaginationState>('Init', async (scope) => {
  scope.page = 0;
  scope.allItems = [];
  scope.hasMore = true;
}, 'init')
  .addFunction('FetchPage', async (scope) => {
    scope.page += 1;
    const items = await fetchPage(scope.page); // your API call
    scope.allItems = [...scope.allItems, ...items];
    scope.hasMore = items.length > 0;
    if (!scope.hasMore) scope.$break();
  }, 'fetch-page')
  .loopTo('fetch-page')
  .build();
```

## Narrative strategies for loops

When loops run many iterations, the narrative grows. Use loop-aware strategies to control output:

```ts
import {
  flowChart,
  FlowChartExecutor,
  WindowedNarrativeFlowRecorder,
  AdaptiveNarrativeFlowRecorder,
  SilentNarrativeFlowRecorder,
} from 'footprintjs';

const chart = flowChart<{ count: number }>('Init', (scope) => {
  scope.count = 0;
}, 'init')
  .addFunction('Tick', (scope) => {
    scope.count += 1;
    if (scope.count >= 8) scope.$break();
  }, 'tick')
  .loopTo('tick')
  .build();
const executor = new FlowChartExecutor(chart);

// Keep first 3 + last 2 iterations
executor.attachFlowRecorder(new WindowedNarrativeFlowRecorder(3, 2));

// Full for first 3, then every 5th
executor.attachFlowRecorder(new AdaptiveNarrativeFlowRecorder(3, 5));

// Summary only — no per-iteration sentences
executor.attachFlowRecorder(new SilentNarrativeFlowRecorder());
await executor.run();
```

<Aside>
  The narrative shows "On pass N through X." for each iteration (FlowRecorder strategies). Custom recorders get the iteration number directly: `FlowRecorder.onLoop(event)` carries `event.iteration` (and `event.target`), and every flow event's `traversalContext.loopIteration` reflects the current pass — use either for custom loop reporting.
</Aside>
